### Fixed
- **Local development secrets now come from Doppler, not `.env.local` files.** `doppler.yaml` maps `packages/api`, `apps/app` and `apps/www` to the `dev_api`, `dev_app` and `dev_www` branch configs of a single `turbostack` Doppler project, and each package's `dev` script — plus a new `packages/api` `convex` script for any other CLI command — runs under `doppler run`. `pnpm setup:envs` is now `doppler setup --no-interactive` instead of copying `.env.example` placeholders (`scripts/setup.mjs` is removed); run it once per checkout and per git worktree, since Doppler remembers its selection by absolute path. The `.env.example` files now list what each config holds rather than acting as templates. *Why one project with per-package configs* rather than a project per package as in sibling repos: the Doppler free plan caps a workplace at 10 projects. `dev_api` holds a dev `CONVEX_DEPLOY_KEY`, so `pnpm dev` no longer needs `npx convex login`. **Production and the e2e suite are untouched:** Vercel keeps its own values, and the suite never runs under Doppler — its `apps/www` server now gets `NEXT_PUBLIC_CONVEX_URL` from `playwright.config.ts` (the same local-backend or placeholder URL as the app server) instead of silently relying on `apps/www/.env.local`, which would otherwise break local runs once that file is gone.

### Changed
- **The Playwright harness is now separate from the specs, and the suites moved from `apps/` to a root `e2e/`:** `apps/e2e-app` → `e2e/app` and `apps/e2e-www` → `e2e/www` (package names, `pnpm test:e2e:*` scripts and `turbo.json` task keys unchanged). Everything about *how an app is driven* moved into `packages/e2e-kit`: the Vite/Next/Convex servers on free ports, the Convex backend (`local-backend.ts`, `scripts/convex-local.mjs`), its identity guard and seed (`global-setup.ts`), and the page objects. A suite is now a thin `playwright.config.ts` calling `defineAppSuite` / `defineWwwSuite` from `@repo/e2e-kit/suites`, plus its specs; page objects come from `@repo/e2e-kit/page-objects` and the seed constants from `@repo/e2e-kit/seed`. `convex:local` moved to `pnpm --filter @repo/e2e-kit convex:local`. Each suite's Next distDir is now `.next-<suite name>` (`.next-e2e-www`); the old `apps/www/.next-e2e` can be deleted. *Why:* projects built from this template add a marketing suite that walks the same page objects under `playwright test` to capture screenshots for promo videos, and it has to boot the apps exactly as the specs do — so the harness can't belong to the specs. The suites sit in a root `e2e/` rather than in `apps/` (which should hold only deployables) or inside each app (where a spec-only commit would count as a change to a deployed package and trigger a production build, and `next build` would typecheck Playwright code).

### Fixed
- **Two suites seeding the same Convex database in one checkout are now refused, not just two runs of one suite:** the run lock used to be keyed on the suite, so once a second suite (e.g. marketing) uses `defineAppSuite`, it and `e2e-app` could run at once in one worktree and each wipe the other's seed mid-run. `acquireRunLock` now takes one lock per shared resource: the suite's own directory (reports, distDir), and, when `E2E_CONVEX` is on, a checkout-wide `packages/api/.e2e-run.lock` for the database. Verified: a second `defineAppSuite` suite started during an `e2e-app` run was refused with a message naming the database and the holder's pid, while the first ran on to 160/160; the same suite with `E2E_CONVEX=0` ran alongside it and passed; a second `e2e-app` run was still refused on the suite lock. Both suites also pass normally (`e2e-www` 11/11, `e2e-app` 4/4), and `packages/api/.env.local` was byte-identical afterwards.

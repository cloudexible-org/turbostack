### Changed
- **Changelog entries are now one fragment file per change, gathered into `docs/changelog.md` only at release:** each change adds `docs/changelog.d/<YYYY-MM-DD>-<branch-slug>.md` holding the Keep a Changelog headings and entries it would have added under `## [Unreleased]`; `docs/changelog.md` no longer has an Unreleased section, and its former entries moved into fragments, one per originating commit. New `scripts/changelog/` (plain Node, no dependencies, ported from instaclub with its `prod`-branch handling dropped): `check` validates every fragment and runs in `pnpm lint`; `check --pr <base>` runs in CI and fails a PR into `main` that edits `docs/changelog.md` unless its branch is `release/*` or it carries the `changelog-edit` label; `pnpm changelog:preview` prints the next release; `pnpm changelog:release <version> [--date …] [--only …]` writes the fragments as `## [<version>] - <date>` and deletes them. Its unit tests run in `pnpm test`. The release step (a `release/<version>` PR that bumps versions and runs `changelog:release`) is now written down in `docs/changelog.d/README.md` and `AGENTS.md` §3. *Why:* every PR added its entry on the same line at the top of `## [Unreleased]`, so any two open PRs — and parallel agent worktrees — conflicted there, and every merge forced a rebase of the rest. Two PRs never add the same file. (#32)
